## Architecture and technology

Java 21+, stable Spring Boot, Maven modules, explicit domain/application/adapter boundaries, Spring Security/Validation/Web, PostgreSQL with Flyway, structured logs and readiness. React/TypeScript dashboard and MV3 extension. One thin authenticated MCP server sharing application services with REST. Separate executable ingestion, AI and communication workers on one EC2. Nginx serves web and proxies API/MCP. Docker Compose; remote Supabase PostgreSQL and private Supabase Storage in production. PostgreSQL outbox with SKIP LOCKED, bounded retries, leases, idempotency and dead-job visibility. No Redis, Kafka, Kubernetes, OpenSearch, vector database, RAG, Step Functions, SQS, mandatory LocalStack or EC2-local production database.

## Product requirements

1. Structured candidate identity, work history, projects, education, skills, certifications, achievements, preferences for roles/companies/locations/salary/remote/visa/notice/outreach/resume. Verified experience facts carry provenance, dates, metrics and skills independently from resume files. Unreviewed extraction never becomes verified automatically.
2. Canonical jobs, all source records, job requirements, hiring and referral posts. Greenhouse, Lever, Ashby, structured career pages and user capture/import through replaceable source ports. No unauthorized social crawling or automated social actions. Preserve source provenance during deterministic normalization/deduplication by external ID, canonical URL, normalized company/title/location, content fingerprint, employment type and posting date.
3. Hard filters before structured matching/ranking and optional top-job AI explanations. Default weights: candidate 40%, freshness 20%, referral 15%, reachability 10%, company 10%, salary 5%. Store explanations, matching/missing skills, fit dimensions and freshness. Expose role/company/location/salary/experience/remote/date/source/referral/contact/score filters, alerts, and direct application links.
4. AI strategy registry with real Gemini, OpenAI and Claude adapters. Default `LLM_PROVIDER=gemini`; select entirely through configuration; cheap/medium/high model IDs independently configurable per provider. Validate only active credentials. Disable fallback by default. Vendor translations stay in adapters. Local JSON schema validation, task limits, timeouts, cancellation, bounded retry/backoff, normalized failures, usage/latency/cost metadata without sensitive prompt logging. Tests are deterministic and never bill live providers.
5. Untrusted page extraction, normalization, sanitization and classification. Clearly separate untrusted data from system instructions. LLM output cannot authorize privileged actions or invent candidate/contact facts. Validate grounding outside prompts, including employers, dates, skills, numbers and URLs.
6. PDF and DOCX resume ingestion with explicit parsing failures and source provenance. Structured canonical resume, verified-fact selection/rewriting, immutable versions, deterministic single-column PDF/DOCX rendering and extraction validation. Internal compatibility dimensions: requirements 30, skills 20, experience 20, parseability 15, keywords 10, formatting 5. Recommendation requires compatibility >=80 AND parsing >=95. Bounded grounded repair cycle and scoring history; never guarantee an employer's ATS outcome.
7. Recruiter research through a replaceable public web-search provider, production adapter and test stub. Store real discovered identities/contact values with source URL/type, confidence, verification status/method/time. Inferred email never sendable. Phone enrichment disabled; paid enrichment only opt-in after public research for shortlisted roles. Related jobs and contact/response history.
8. Fact-grounded email, LinkedIn and WhatsApp drafts with templates, tone, instructions and length variations. Social messages copied/opened for manual sending only.
9. Outreach states GENERATING, DRAFT, AWAITING_APPROVAL, REJECTED, APPROVED, QUEUED, SENDING, FAILED, SENT. Immutable approval binds exact recipient, email version, resume version and attachment. All edits invalidate it. User previews the exact final bytes/content before explicit approval. Neither REST nor MCP bypasses approval. Separate communication worker validates approval again. Gmail API and Microsoft Graph adapters, encrypted OAuth refresh tokens and non-sending test mode. Handle ambiguous network-send outcomes without blind duplicate sends.
10. Application states DISCOVERED, SAVED, SHORTLISTED, PREPARING, READY_TO_APPLY, APPLIED, OUTREACH_PREPARED, OUTREACH_SENT, REPLIED, INTERVIEW, OFFER, REJECTED, WITHDRAWN. Validate transitions and record append-only history. Dashboard tracker and outcome/source/resume/template analytics.
11. Full responsive accessible dashboard: OAuth login/logout/session handling; profile/preferences; resume upload/review/download/history/comparison/scores; ranked search; job detail with provenance/gaps/recruiters; application history; exact outreach approval; connectors, async status and analytics.
12. MV3 React extension with user-triggered current-page capture (URL/title/visible text/structured metadata), authenticated calls, analyze/match/save/tailor/outreach/dashboard actions; minimal permissions, no background crawl. Same account as web, PKCE where applicable, no frontend refresh tokens.
13. MCP jobs.search/get/analyze; resume.tailor/evaluate/render; recruiter.find; outreach.generate_email/linkedin/whatsapp; applications.create/update; useful read tools. Schema validation, authenticated user ownership and controlled errors. No arbitrary email tool or duplicate business logic.

## Persistence and security

Durable tables: users, candidate_profiles, experience_facts, resumes, resume_versions, jobs, job_sources, job_requirements, job_matches, recruiters, contact_points, job_recruiters, applications, application_events, outreach_messages, outreach_versions, approvals, connector_configs, connector_runs, audit_events, outbox_events; normalized supporting tables as needed. Every user-owned record is scoped server-side; composite foreign keys prevent cross-user joins. Immutable version and event history. Versioned migrations create all tables, constraints and indexes on empty PostgreSQL.

OAuth2/OIDC and browser PKCE, backend token validation, encrypted server-held refresh tokens, least privilege, CSRF/CORS/XSS/SQLi/SSRF/upload/path-traversal defenses, private object storage, prompt injection separation, bounded/rate-limited expensive operations. Audit login, resume/research/outreach generation, approvals/invalidation, queuing/sending/failure and application transitions. No secrets or complete prompts in logs. Consistent versioned API DTOs, validation, pagination, errors, OpenAPI and mutation idempotency where needed.
