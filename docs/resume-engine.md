# Resume engine

Upload PDF or DOCX, maximum 10 MB. PDFBox and Apache POI validate actual contents, reject malformed/encrypted/empty/scanned-without-text documents and apply ZIP expansion limits. No OCR or macro execution. Extraction stores both text and structured review sections (identity, work history, projects, education, skills, certifications, achievements and summary), preserving every non-empty source line and its location. Explicit email values and listed skills are extracted without guessing. All imported data remains `REQUIRES_REVIEW`; it does not automatically verify claims or overwrite the canonical profile.

Review extracted text in Resume library, then create structured profile records and verified facts with provenance. Preserve company, role, dates and achievements exactly. V1 deliberately requires user confirmation before extracted content can support generated claims; automatic ingestion of inferred employment facts would be unsafe.

Tailoring is queued in PostgreSQL. The selected provider ranks verified fact IDs against the JD. Unknown/unverified/foreign IDs are rejected. The structured resume has exact candidate identity, evidence-linked sections/bullets and verified skills. PDF and DOCX are deterministic single-column, text-based templates (`classic`/`compact`), not LLM-generated binary layouts. Every version stores input JSON, private object paths, hashes and scoring history. Old versions never change.

Internal scoring uses requirement coverage 30, skills 20, deterministic experience-alignment proxy 20, parseability 15, keyword coverage 10 and formatting 5. The recommendation gate is compatibility ≥80 and parsing ≥95. A failed gate triggers one bounded repair using additional already-verified relevant facts and a classic rerender; it then records reevaluation. If evidence is still missing, the version remains review-required. The engine does not manufacture facts to pass a score.

The experience dimension is a lexical V1 proxy, not embedding/RAG semantics and not an employer ATS score. Parseability compares extracted PDF/DOCX text against structured input, including identity, headings, supplied fact dates and education. Education is copied from the user's canonical profile, never generated by the model. Unknown employment dates are left unknown. No external ATS acceptance or interview outcome is guaranteed. The user can consciously approve a review-required version after inspecting it; the label is never hidden.

Font: `RESUME_FONT_PATH` in containers uses packaged DejaVu Sans. Windows host tests use `-Dmyjobai.resume.font=C:/Windows/Fonts/arial.ttf`; other systems can set an installed TTF path. Unsupported glyphs/document corruption cause explicit failure. Broader international font coverage and OCR are future enhancements, not fabricated success.

Tests perform real PDF and DOCX rendering/extraction, deterministic byte comparisons, corrupt/spoof rejection, provenance validation and API generation/approval flows. The dashboard supports download, score history and structured comparison of two versions.
