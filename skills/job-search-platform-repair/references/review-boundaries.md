# Repository-specific fault lines

Read these as review targets, not a frozen implementation map; locate current owners in code.

- **Cost V1:** production is one EC2/Compose with remote Supabase PostgreSQL and private object storage. Test PostgreSQL is isolated. Reject accidental Redis/Kafka/Kubernetes/OpenSearch/SQS/vector/RAG requirements. Check model tiers, request budget, canonical cache identity, usage accounting after failures/rollbacks and research eligibility filters.
- **Shared use cases:** REST, extension capture and MCP must reach application services. Domain/application must not import vendor infrastructure. MCP handlers must not independently implement matching, approval or send logic.
- **Ownership:** queries and updates require authenticated owner predicates; composite FKs protect attachments/contacts/jobs. Test foreign resource IDs on reads and every mutation, not only jobs. Never trust `userId` from request bodies. Auth-state/code/session/refresh-token ownership and one-use PKCE exchanges matter too.
- **Facts and resumes:** uploads are untrusted; extraction success differs from verified truth. Candidate identity and verified facts are canonical. Trace every rendered claim, skill, company, metric and date. Check zip/file limits, parse failures, immutable versions, byte-stable files, rendering/extraction, score dimensions, 80/95 gate and bounded repair history. Do not replace a strict validator with “the LLM says it is grounded.”
- **Email:** approval binds exact version/recipient/resume/hash; edit invalidates it atomically. Recheck at reservation and attachment fetch. Lock state before provider POST. A timeout/crash after POST is uncertain delivery, not proof of failure; do not blindly resend. Reconciliation is an explicit human record, never a send bypass. Failed retries must not leave QUEUED forever. Social output remains manual.
- **Outbox:** mutation and enqueue are one transaction; concurrent claims use SKIP LOCKED; lease tokens fence stale completion; recover leases, enforce max attempts and expose terminal jobs. Provider acceptance cannot be made exactly-once through PostgreSQL alone.
- **External data:** URL validation must cover DNS resolution/rebinding, private/reserved addresses and redirects. Page text is untrusted data, not authority. Research contacts need actual public source evidence; no guessed recruiter identity/address/profile. An empty result is valid and must not be disguised as success with fabricated data.
- **Auth/logs:** production OAuth/PKCE BFF, encrypted server refresh tokens, issuer/audience/time/signature checks, CSRF for cookies, restricted CORS and extension redirects, short-lived MCP/extension access. No provider body, request secret, OAuth query or debug token logging. Test mode must fail closed outside explicit loopback/test topology.
- **Operations/contracts:** all five Java executables must package and start; worker ports stay private. Verify generated OpenAPI, browser DTOs, all MCP tools and error shapes against actual servers. Validate TLS file paths/readability, upload/body limits, Compose override semantics, early prerequisite checks, idempotent non-destructive deployment, backup recovery and restart persistence.

For every finding capture the smallest reproduction and a regression assertion. A mock in a named test provider is expected; the defect is selecting it in production. An architectural interface is not sufficient evidence that its real adapter works.
